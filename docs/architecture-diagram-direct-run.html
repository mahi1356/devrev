Direct run — wiring sanity check

Running main_orthestrator.py on its own (no harness, no dataset) is the fastest way to confirm the developer and reviewer agents can actually reach Ollama and talk to each other. It uses a hardcoded placeholder task and no starting code, and nothing checks whether the output is correct. For a real, verified bug fix see the QuixBugs harness diagram instead.

  1. Run the file directly. python3 src/main_orthestrator.py executes its __main__ block, calling run("Describe your task here") with no starting code.
  2. Set up the loop. run() creates a DeveloperAgent, a ReviewerAgent, and a fresh ConversationLogger, which immediately creates logs/<timestamp>.json.
  3. Developer responds. DeveloperAgent.run() sends the placeholder task (plus empty code/feedback) to Ollama; the model's reply becomes the round's code. Logged.
  4. Reviewer responds. ReviewerAgent.run() sends that code to Ollama and either critiques it or replies APPROVED. Logged.
  5. Print the round. The code and review for the round are printed to the console as --- Round N ---.
  6. Loop or exit. If the reply contains "APPROVED" the loop breaks immediately (even on round 1); otherwise it feeds the feedback into another developer round, up to 3 rounds total.
  7. Return, no verdict. The log path is printed and the final code string is returned — nothing runs it, tests it, or checks it against anything.

What it proves

  • Ollama is reachable at 127.0.0.1:11434 and the qwen2.5-coder:7b model responds to .chat().
  • The developer/reviewer loop wiring — passing code and feedback back and forth — works end to end.
  • ConversationLogger correctly writes a transcript to logs/.

What it does not prove

  • Whether the developer's fix is actually correct — there's no task-specific code and nothing checks the output.
  • Whether the agents behave the same way on a real bug — the hardcoded task is a generic placeholder, so the model effectively invents its own toy example.
  • For that, use the QuixBugs harness, which feeds a real buggy program through the same loop and checks the fix with pytest.
Same known gap as the harness path: the loop only breaks early on the literal substring "APPROVED". If the model writes "Approved" or phrases approval differently, the check misses it and the loop just burns through all 3 rounds.
